## Review and rollout

Independent review covered database fences, deletion containment, scheduler lifecycle, access
guards, retained history and UI expiry behavior. Findings about bounded orphan-scan fairness,
upload rearming and disappearing descendants were repaired and rechecked. The integration suite
also caught and verified the fix for SQL aliases conflicting with existing function variables.

The full gate exposed an existing database shutdown race: pg-pool removes idle clients from its
count before their socket end callbacks finish, so forced test-database removal could interrupt
connections still closing. The shared database closer now tracks public connect/end events and
waits for every connected client to disconnect, including connections finishing during shutdown.
Three regression tests cover early pool completion, previously disconnected clients and late
connections; the affected integration suites verify clean teardown.

Apply forward migrations 0044–0046 before updated API/worker startup. Existing source/output
deadlines remain unchanged; retention configuration only affects newly accepted/published media.
Hourly cleanup deletes bytes on the next eligible pass while access enforcement is immediate.
See [ADR 0008](../adr/0008-file-retention.md), [environment settings](../env-reference.md) and
[schema documentation](../database-schema.md).
