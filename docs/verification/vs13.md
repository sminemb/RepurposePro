## Decisions and implementation

- Resend HTTP API, without a new SDK dependency. Server-only configuration:
  `RESEND_API_KEY` and `RESEND_FROM`, required at startup in staging and production.
- Local environments may omit both settings; email actions then fail closed while profile and
  password controls remain usable. Incomplete configuration is rejected without secret values.
- Existing unverified users verify their current email first. Current-address approval then
  precedes new-address verification; signup/login verification policy remains unchanged.
- Better Auth owns account updates, credentials, sessions, and tokens. Its account-email context
  extension propagates delivery failures instead of silently accepting a failed send.
- Profile/password/email requests use independent Arcjet policies after authentication;
  verification URLs and provider failures are omitted from application logs.
- No database migration, new dependency, or separate account API.

### Controlled inbox procedure

1. Configure `RESEND_API_KEY` and `RESEND_FROM` in the ignored root `.env`. The sender must be
   verified in Resend. Restart the web app after configuration changes.
2. Use an account whose current email is an inbox you control. If unverified, choose
   **Verify current email**, confirm delivery, and open that link.
3. Enter a second controlled inbox (a deliverable alias is acceptable) and request a change.
   Confirm approval mail arrives at the current address; approve it.
4. Confirm verification mail arrives at the second address. The active email must remain the
   original address until this final link is opened.
5. Open the final link and confirm Settings and a fresh login use the new verified email.
6. Record the date, message types, provider delivery status, and observed result here. Redact
   credentials, tokens, cookies, passwords, and mailbox addresses from committed evidence.
