# VS11 verification

Started 2026-10-03 at 08:19 Asia/Manila. Work is on `codex/vs11-hardening`.

## T1 — Abuse protection

API mutations use Shield, bot detection and separate per-user/action fixed-window budgets.
Signup/login use the actual Better Auth Next.js route with separate client-IP/action budgets.
The shared decision adapter rejects error and malformed decisions safely; rate limits return
429 with Retry-After, attacks return 403, and unavailable protection returns 503 before mutation.
Existing Checkout and analysis unavailable codes are preserved. Auth response bodies remain
Better Auth compatible. Session/logout/read routes and signed Stripe webhooks are excluded.

Local/test auth deliberately uses loopback identity. Production web auth requires Vercel's
overwritten `x-vercel-forwarded-for` header and rejects unsupported ingress. API client IP
headers are discarded unless the socket peer matches `ARCJET_TRUSTED_PROXIES`. That proxy
must replace X-Forwarded-For and prevent bypass of the configured ingress. Only server-side
Arcjet credentials are used. Production requires LIVE; local DRY_RUN remains supported.

Focused protection tests: 17 passing. A failing request-body-consumption test reproduced the
auth wrapper defect before the fix. SDK decisions in these tests are mocked; live Arcjet smoke
results are recorded separately below.
Full T1 validation: 659 unit tests and 121 PostgreSQL/Redis integration tests passed; workspace
typecheck and focused lint passed. Independent review caught the SDK's Date-valued reset time;
the adapter now handles it and a regression verifies the ten-minute signup Retry-After.

## T3 — Uploads and storage

Added an ownership/eligibility guard before multipart staging, retaining the service's second
check for races. Multipart input permits one file, no fields, one part, bounded headers and
the configured size limit. Extension/MIME validation runs before disk writes; actual probing,
audio validation and the 30-minute cap remain in place. HTTP regressions revealed that Nest
transforms Multer errors before the old filter and that a size rejection can happen before
asynchronous retention registration assigns a path. Both cases now return the documented
envelopes and clean up safely, while interruption still releases the durable upload lease.

Private-storage operations inspect existing ancestors and reject symlinks/junctions, even
links pointing inside storage. Reads, rename destinations and recursive removals are checked;
source/download streams use opened file handles with regular-file/size checks. Added tests
prove junction targets remain unchanged. Protection HTTP tests verify the production guard
registration and denial before each new protected handler or upload staging.

Verification: 90 focused domain/storage tests plus 9 HTTP regressions passed. Workspace
typecheck passed. Deterministic protection decisions are mocked, separate from live smoke.

## T4 — Queue contracts and subprocesses

Analysis already validates its supported job name, plain payload, UUIDs and queue-ID agreement.
Regeneration and clip/summary rendering now share exact resource-payload validation. Framing
requires `{id: UUID}`, `track_faces` and matching queue ID; string coercion is removed. Cleanup
requires its supported name, bounded scheduler ID and an empty plain payload before sweeping.
All work resolves its source, owner, snapshots and paths from restricted durable database state.

Worker reads/moves/removals reject storage links and escapes. Executable configuration accepts
only media/Python binaries, with fixed server-authored arguments and no shell. FFmpeg/ffprobe
input protocols are limited to file/pipe. Audio extraction now has a five-minute bound;
existing Python/render cancellation and output bounds remain. Probe results validate finite
durations and bounded dimensions. Media errors no longer carry raw stderr. Added ingress and
subprocess regressions verify no database calls for invalid jobs, timeout/cancellation,
bounded output and command substitution rejection. Python scripts/model paths are operator
configuration; queue payloads cannot supply scripts, executable paths, flags or media paths.

## T6 — Gemini

Existing selectors validate bounded strict JSON, finite source timestamps, candidate/segment
counts, ordering and overlap before database persistence. Clip selection retains its valid
partial fallback; summary selection requires a wholly valid chronological selection.
Transcript data escapes closing tags and the system instruction explicitly rejects transcript
commands. Added regressions exercise hostile text, repair exhaustion, oversized/malformed JSON,
timeouts even when the SDK ignores cancellation, and successful output arriving after abort.

Clip/summary selection now have an application timeout in addition to the SDK timeout; all
selection calls disable hidden transport retries. Non-durable repair loops are capped at three
calls too. Durable stage counters still reserve each call before external work and share three
total calls across crashes/delivery retries. Summary transport failures now use GEMINI_FAILED
classification so the existing eligible, exactly-once refund path applies. Cached transcripts,
execution leases and retention rules remain unchanged.

## T7 — Logs and errors

Expected framework HTTP errors now retain their status and use a safe domain envelope; existing
domain codes/envelopes pass through unchanged. Unexpected failures retain generic 500 responses.
Shared API/worker logging allowlists retain processing/protection context and exclude raw
request URLs, bodies, headers, credentials, cookies, transcripts, provider objects, paths and
subprocess errors. Incoming request IDs are limited to 64 safe characters. SDK diagnostic logs
are disabled in favor of structured protection outcomes, including simulated DRY_RUN denials.
Worker startup failure output no longer includes raw exception text.

Injected secret-marker tests capture both API/worker logger output and actual pino-http request
completion logs, including child request bindings. Credentials, cookie/response headers, body,
private URL/query, transcript and error markers do not appear; safe stage IDs remain available.
The full unit run exposed an older test expecting a raw source-validation Error in logs; that
expectation was corrected to verify safe identifiers only. No source-error content is logged.

API UI adapters map 429 Retry-After to seconds, 503 to a temporary outage, and 403 to refresh
guidance. Signup uses the ten-minute window and login one minute. Framing retains manual fallback.
Focused T7 verification passed 53 protection/error/UI tests, plus actual HTTP log redaction and
source-preview regression checks. Full CI evidence is recorded below after completion.

Real production components were bundled into an ignored local fixture, with navigation/server
plumbing adapted and a deterministic backend. Chrome DevTools used an isolated test context.
This verifies rendering and event handling; database and live Arcjet evidence are separate.
No accounts, purchases, credit deductions or paid jobs were created by the browser fixture.

### Live Arcjet smoke — separate from mocked tests

Synthetic local requests exercised the actual Node and Next.js adapters with the configured
server credential. Calls run only protection; they never invoke mutations. Initial Node calls
timed out and safely returned 503. Subsequent Node and Next.js calls returned allowed decisions.
In the final Node LIVE sequence, the initial timeout returned 503, the next three requests

A LIVE curl bot returned `403 REQUEST_BLOCKED`; the same bot in DRY_RUN returned a simulated
denial, logged as `dry_run_denied`, with status 200. Intermittent provider timeout decisions
remained fail-closed. Next.js local login protection returned an allowed decision too.

Production ingress and deployed LIVE enforcement remain deployment checks; no deployment was
requested. API proxy spoofing and web ingress requirements have deterministic regression tests.

### Tooling notes

Full formatting validation initially rejected Windows checkout line endings and a few earlier
test layouts. Prettier corrected these; unchanged normalized files introduce no behavior change.
The new real HTTP log test declares the already-locked `pino-http@11.0.0` as an API development
dependency. The lockfile retains all previous dependency versions and resolutions.

Registry metadata retries interrupted the subsequent frozen reinstall. The exact cached graph
was synchronized with a one-off offline/frozen install using `minimumReleaseAge=0` and
`trustPolicy=off`; no configuration override was saved and no package version was upgraded.
The installer reported successful lockfile verification under those one-off settings. Its
local installation metadata records the temporary minimum release age, so default pre-script
verification triggers another install and retries inaccessible registry metadata even while
reporting the installed packages up to date. Final CI temporarily sets
`pnpm_config_verify_deps_before_run=warn`, so every normal quality-gate command runs against
the installed cached graph without another automatic reinstall. This is an environment-only
workaround; normal policy verification should be retried when registry access recovers.
