## T1 — Abuse protection

API mutations use Shield, bot detection and separate per-user/action fixed-window budgets.
Signup/login use the actual Better Auth Next.js route with separate client-IP/action budgets.
The shared decision adapter rejects error and malformed decisions safely; rate limits return
429 with Retry-After, attacks return 403, and unavailable protection returns 503 before mutation.
Existing Checkout and analysis unavailable codes are preserved. Auth response bodies remain
Better Auth compatible. Session/logout/read routes and signed Stripe webhooks are excluded.

Local/test auth deliberately uses loopback identity. Production web auth requires Vercel's
overwritten `x-vercel-forwarded-for` header and rejects unsupported ingress. API client IP
headers are discarded unless the socket peer matches `ARCJET_TRUSTED_PROXIES`. That proxy
must replace X-Forwarded-For and prevent bypass of the configured ingress. Only server-side
Arcjet credentials are used. Production requires LIVE; local DRY_RUN remains supported.

Focused protection tests: 17 passing. A failing request-body-consumption test reproduced the
auth wrapper defect before the fix. SDK decisions are mocked; live Arcjet smoke is pending.
Full T1 validation: 659 unit tests and 121 PostgreSQL/Redis integration tests passed; workspace
typecheck and focused lint passed. Independent review caught the SDK's Date-valued reset time;
the adapter now handles it and a regression verifies the ten-minute signup Retry-After.

## T3 — Uploads and storage

Added an ownership/eligibility guard before multipart staging, retaining the service's second
check for races. Multipart input permits one file, no fields, one part, bounded headers and
the configured size limit. Extension/MIME validation runs before disk writes; actual probing,
audio validation and the 30-minute cap remain in place. HTTP regressions revealed that Nest
transforms Multer errors before the old filter and that a size rejection can happen before
asynchronous retention registration assigns a path. Both cases now return the documented
envelopes and clean up safely, while interruption still releases the durable upload lease.

Private-storage operations inspect existing ancestors and reject symlinks/junctions, even
links pointing inside storage. Reads, rename destinations and recursive removals are checked;
source/download streams use opened file handles with regular-file/size checks. Added tests
prove junction targets remain unchanged. Protection HTTP tests verify the production guard
registration and denial before each new protected handler or upload staging.

Verification: 90 focused domain/storage tests plus 9 HTTP regressions passed. Workspace
typecheck passed. Deterministic protection decisions are mocked, separate from live smoke.

## T4 — Queue contracts and subprocesses

Analysis already validates its supported job name, plain payload, UUIDs and queue-ID agreement.
Regeneration and clip/summary rendering now share exact resource-payload validation. Framing
requires `{id: UUID}`, `track_faces` and matching queue ID; string coercion is removed. Cleanup
requires its supported name, bounded scheduler ID and an empty plain payload before sweeping.
All work resolves its source, owner, snapshots and paths from restricted durable database state.

Worker reads/moves/removals reject storage links and escapes. Executable configuration accepts
only media/Python binaries, with fixed server-authored arguments and no shell. FFmpeg/ffprobe
input protocols are limited to file/pipe. Audio extraction now has a five-minute bound;
existing Python/render cancellation and output bounds remain. Probe results validate finite
durations and bounded dimensions. Media errors no longer carry raw stderr. Added ingress and
subprocess regressions verify no database calls for invalid jobs, timeout/cancellation,
bounded output and command substitution rejection. Python scripts/model paths are operator
configuration; queue payloads cannot supply scripts, executable paths, flags or media paths.
